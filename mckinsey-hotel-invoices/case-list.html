Decisions applied here

Case age counts from checkout date, not intake — it doubles as the countdown to Chase Needed · search covers confirmation no., PNR, FMNO, traveller and hotel · row click opens the case detail view · "Assign to me" appears inline on unassigned Chase Needed / Ingestion Exception rows · every column header is sortable · the Hotel field is a typeahead filter, separate from and additive with the search box and status chips.
Bulk export: selecting cases and clicking Export CSV only shows the interaction point — the toast simulates the action, no file is actually generated. The real export job runs on the backend.
Column density: the seven core columns stay fixed; PNR and FMNO are lookup fields hidden behind the "Columns" picker. Exception reason shows as secondary text under the status pill rather than its own always-on column, since it's only meaningful on rows that already have a problem.
Status escalation: Chase Needed ages from amber to red at a threshold (10 days, shown on CNF-88250) rather than becoming a new status — same pill, same label, escalated color + icon.
Empty / live state: filtering is instant and client-side here; in the real build, filter results must reflect live case status, never a stale page load, per the PRD.
