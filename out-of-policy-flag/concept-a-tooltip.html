Concept A — Tooltip

The current pattern. A lightweight popover anchored to the flag icon, no header chrome, no explicit close button. Opens on hover, click, or tap; auto-dismisses 3 seconds after the pointer actually leaves it. Small/medium/large only change the flag icon's size (16/18/20px) — the tooltip's content, width, padding, and type are the same at every size.

Decisions applied here

Small/medium/large change only the flag icon's size (16/18/20px) — the tooltip itself (width, padding, "Out of Policy" title, message copy) is identical at every size, shown standalone above · hover, click, and tap all open it — the standard interaction for both tooltip and popover going forward · no close button, so it auto-dismisses 3s after the pointer leaves the trigger (not 3s from the click) · keyboard focus reveals it via :focus-visible, and every close path calls blur() so a lingering keyboard focus ring can't keep it visually stuck open · five placement variants (below, above, left, below-left, above-left) — below/above center the tooltip on the trigger, left is vertically centered beside it, and the "-left" variants stay flush to the trigger's right edge and grow leftward instead of rightward, which is what both card examples actually need since their flag sits at the right edge of the price column · card examples default to the small icon size · the Flight card renders the same tooltip with list-format content (two numbered violation reasons) instead of a single sentence — same component, same interaction, different content shape driven entirely by data.
