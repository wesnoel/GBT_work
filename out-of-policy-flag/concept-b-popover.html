Concept B — Popover dialog

A heavier, structured popover — still anchored to the flag, not a full modal. Has a real header (icon + title) and an explicit close button. Opens on hover, click, or tap — the standard interaction for both tooltip and popover going forward. Small/medium/large/extra large only change the flag icon's size (16/18/20/24px) — the popover's content, width, padding, and type are the same at every size.

Interactions
  1. Hover, click, or tap all open it — the same trigger behavior on desktop and mobile-web.
  2. Auto-dismisses after idleCloseDelay (default 3000ms) once the pointer actually leaves the trigger/Dialog — timed from leaving, not from the moment it opened, so reading it doesn't race a clock.
  3. Tab to the flag reveals it via keyboard focus; Escape or clicking anywhere outside it closes it.
  4. Has an explicit × close button; idle-dismiss still runs underneath it as a safety net, in case someone opens it and walks away without closing.
  5. Opening any instance closes whichever other one is already open — only one Dialog is ever visible at a time, page-wide.
Automatic viewport positioning
  1. Default is Above, left on desktop and tablet.
  2. Below the mobile-web breakpoint, the default instead centers horizontally on the trigger and auto-flips Above/Below toward whichever side has more room.
  3. Whichever placement is active — default or explicit — the Dialog is nudged to stay at least viewportMargin inside the viewport on every edge, recalculated on open, hover, keyboard focus, and live on window resize.
  4. An explicit placement is respected as the starting position; the clamp only nudges it back on-screen, it never swaps to a different side.

Decisions applied here

Small/medium/large/extra large change only the flag icon's size (16/18/20/24px) — the popover itself (width, header, body, footer, type) is identical at every size, shown standalone above · hover, click, and tap all open it — the standard interaction for both tooltip and popover going forward, superseding an earlier click/tap-only version of this concept · has an explicit close (×) button, but still auto-dismisses 3s after the pointer leaves in case someone opens it and walks away without closing · keyboard focus reveals it via :focus-visible, and every close path (timeout, × button, outside click, Escape) calls blur() · five placement variants (above-left, below, above, left, below-left) — **above, left is the default** (revised 2026-10-01; was below, centered), flush to the trigger's right edge and growing up and to the left, since that's what the hotel/flight card actually needs given its flag sits at the right edge of the price column; below/above center the popover on the trigger, left is vertically centered beside it · the card examples default to the medium icon size (revised from small). The same popover applied to the Flight/Air SRP card lives on its own page — see Flight — Popover dialog. Full write-up: design-decisions.md.
